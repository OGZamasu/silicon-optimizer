Measurement

Every number the app shows you is derived, then checked.

Most tools estimate model memory as file size plus a bit. That is wrong in ways that matter at 30B. These figures come from llama.cpp's own buffer accounting and from footprint(1), against predictions made before the model was loaded.

The KV cache figure is exact because it is arithmetic, not estimation: 2 × layers × kv_heads × head_dim × context × bytes. Head dimension is read from the model file rather than derived — Qwen3 keeps a 128-wide head on a 2048-wide residual stream, and deriving it as d_model / n_heads puts that whole family out by a factor of two.

The 7B row is the outlier, and it is why the app ships a benchmark. Running it measures the model on your machine and corrects later estimates for that model only — architectures differ enough that one global correction makes other predictions worse.

Mixture-of-experts streaming

A 30B model in 5.3 GB.

With llama.cpp's on-demand expert paging, only a pool of experts stays resident and the rest are read from the GGUF as the router asks for them. Output is numerically identical — only residency changes.

All resident
19.0 GB
24 of 128 experts
5.32 GB

Predicted 5.2 GB, measured 5.32 GB. The cost is prompt processing: the expert pool has to hold every expert the in-flight batch could pick, so the micro-batch collapses to 3 tokens and ingestion falls from 895 tok/s to roughly 11. Generation drops from 89 tok/s to 26. The app states this before you turn it on, rather than after.

Expert paging is not in any llama.cpp release yet. Silicon Optimizer probes the binary for the flags and disables the option when they are missing, instead of letting the load fail.

What it does

No Terminal, no flags, no arithmetic.

Reads your actual hardware

Chip generation, performance and efficiency core split, GPU cores, memory bandwidth, disk headroom — probed from sysctl and the IORegistry, no elevated privileges.

Picks the model for you

One button. The best model your Mac can actually run, at a context length that is useful, with a tokens-per-second figure you can check.

Explains a bad fit

When something will not fit you get a ranked list of what to change — context length, KV cache precision, quantization, expert streaming — each with the exact saving.

Lives in the menu bar

Current model, memory, GPU load and tokens per second at a glance. Downloads resume after interruption and are verified by checksum.

Model Context Protocol

Let Claude or ChatGPT drive the model you already have loaded.

A bundled MCP server bridges to the running app, so an assistant uses your loaded model rather than starting a second copy and doubling the memory bill. The chat tool runs entirely on your machine — nothing leaves it.

Known limits

What is measured, and what is not.

The engine is well covered — 88 unit tests plus network, runtime and download-recovery suites — and every number on this page was measured rather than estimated. These are the edges that have not been exercised yet, listed so you know where you stand.

  • Calibrated on one machine. An M3 Max with 38.7 GB. Other chips are predicted from published bandwidth figures; the built-in benchmark corrects for yours in about a minute.
  • Not notarized yet. Building from source signs locally and avoids the Gatekeeper prompt entirely.
  • Expert streaming needs a patched llama.cpp. The flags have not landed in a release build. The app probes for them and hides the option when they are absent.
  • MLX runs, but has no catalog entries. The runtime is verified against a real mlx_lm.server; point it at a model directory yourself for now.
  • Split-file models resolve but have not been transferred. Shard order and totals are checked against Hugging Face; the multi-part download itself is unexercised.

Install

Build it, then point it at a runtime.

1 · Build the app

# Requires Xcode 16+ and macOS 14 or later on Apple Silicon
git clone https://github.com/OGZamasu/silicon-optimizer
cd silicon-optimizer
Scripts/build-app.sh --release
cp -R "build/Silicon Optimizer.app" /Applications/

2 · Install a runtime

brew install llama.cpp                              # GGUF models
python3 -m venv ~/.silicon-mlx
~/.silicon-mlx/bin/pip install mlx-lm               # optional, MLX

3 · Connect Claude or ChatGPT

Scripts/install-mcp.sh --configure-claude

The app finds runtimes automatically, including inside a Python virtual environment — which is where mlx-lm has to live on modern macOS. Settings shows what it found and whether that build supports expert streaming.
